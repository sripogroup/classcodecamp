# ⚡ Solar Guard — เฝ้าระวังการใช้ไฟจากโซลาร์ แล้วแจ้งเตือนพนักงานให้ไปลดโหลด

ระบบที่คอยกัน **ไม่ให้ค่าเฉลี่ย 15 นาทีของไฟที่ซื้อจากการไฟฟ้าแตะ 30 kW** — เพราะเดือนไหนแตะแม้แค่ครั้งเดียว จะถูกย้ายไปค่าไฟประเภทที่ 3 และต้องคุมให้ต่ำกว่า 30 kW ติดต่อกัน **12 เดือน** ถึงจะกลับมาได้

เมื่อไฟหลวงเริ่มเข้าเยอะ ระบบจะเตือนพนักงานพร้อม **บอกเลยว่าให้ไปปิดอะไรบ้าง** และถ้าเปิดใช้ ก็ **สั่งปิดแอร์เองอัตโนมัติ** ได้

- ⏰ **เฝ้างานประจำ** เช่น "ปิดแอร์ 15:00" — ถ้าถึง 15:10 แล้วโหลดยังไม่ลด แปลว่าไม่มีใครทำ เตือนทันที
- 🏭 ดึงข้อมูลจาก **Huawei FusionSolar** (Northbound API)
- ☁️ รันบน **Cloudflare Workers** — ไม่ต้องมีเซิร์ฟเวอร์ ไม่ต้องรัน Node ค้างไว้บนเครื่องไหนทั้งนั้น
- 📊 คิด **ค่า demand ตามหน้าต่าง 15 นาทีจริง ๆ** แบบเดียวกับที่การไฟฟ้าคิด พร้อมติดตามพีคของเดือน
- 💬 แจ้งเตือนทาง **Telegram** (ฟรีไม่จำกัด) + **อีเมล** (เฉพาะเรื่องใหญ่)
- 📺 มี **หน้าจอติดผนัง** ไฟสามสี + เสียงไซเรน + ตัวเลขว่าเหลือระยะถึงเพดานอีกกี่ kW
- 🤖 **ตัดโหลดอัตโนมัติ** พร้อมกฎกันคอมเพรสเซอร์พังและ fail-safe (ปิดไว้เป็นค่าเริ่มต้น)
- 🚨 ต่อ **ไฟหมุนจริง** ทีหลังได้ผ่าน `/api/state` (ดู [`docs/SIREN.md`](docs/SIREN.md))

> 📖 **อ่าน 2 ไฟล์นี้ก่อนใช้งานจริง**
> - [`docs/ALERTING.md`](docs/ALERTING.md) — ออกแบบการแจ้งเตือน ตั้งเกณฑ์ยังไงไม่ให้พนักงานเบื่อจนเลิกสนใจ
> - [`docs/AUTOSHED.md`](docs/AUTOSHED.md) — ปิดแอร์อัตโนมัติ **พร้อมข้อจำกัดที่ต้องรู้ก่อนไว้ใจระบบ**

## สถานะตอนนี้

| หัวข้อ | สถานะ |
|---|---|
| โค้ดทั้งระบบ | ✅ เขียนครบและ commit แล้ว |
| ตรรกะการเตือน / คิด demand / เฝ้างานประจำ / ตัดโหลด | ✅ ทดสอบแล้ว 106 ข้อ ผ่านหมด |
| เส้นทางเต็ม (ดึงข้อมูล → ส่ง Telegram → เก็บ KV) | ✅ ทดสอบแล้วโดย**จำลอง** API |
| มีมิเตอร์วัดฝั่งการไฟฟ้าไหม | ✅ **ยืนยันแล้วว่ามี** (ดูหลักฐานข้างล่าง) |
| ต่อกับบัญชี FusionSolar จริง | ❌ **ยังไม่เคย** — ต้องใช้บัญชี Northbound API ของคุณ |
| deploy ขึ้น Cloudflare | ❌ **ยังไม่ได้** — ต้องใช้บัญชี Cloudflare ของคุณ |
| ส่งเข้ากลุ่ม Telegram จริง | ❌ ยังไม่ได้ — ต้องใช้ bot token ของคุณ |

**สิ่งที่ยังพิสูจน์ไม่ได้จนกว่าจะ deploy จริง**: ชื่อฟิลด์และรหัสอุปกรณ์ของ FusionSolar
(`devTypeId`, `active_power`) เขียนตามสเปกของ Northbound API ถ้าบัญชีคุณคืนค่าต่างจากนี้
จะรู้ทันทีตอนเรียก `/api/poll` ครั้งแรก และแก้ที่ `src/fusionsolar.js` จุดเดียว

### ✅ ยืนยันแล้วว่าระบบมีมิเตอร์ — ข้อมูลที่ระบบนี้ต้องใช้มีครบ

ตรวจจากหน้า Monitoring → Overview ของโรงงานจริง (2 ส.ค. 2569) พบว่า:

**แผนภาพการไหลของไฟ** แสดงครบสามทาง และตัวเลขบวกกันลงตัวพอดี:

```
การไฟฟ้า 1.902 kW ─┐
                    ├─► โหลด 13.786 kW        (1.902 + 11.884 = 13.786 ✓)
โซลาร์  11.884 kW ─┘
```

**ตัวเลขรายวัน** ก็แยกฝั่งผลิตกับฝั่งใช้ออกจากกันชัดเจน:

| รายการ | ค่า |
|---|---|
| โซลาร์ผลิตวันนี้ | 128.46 kWh |
| **ซื้อจากการไฟฟ้าวันนี้ (Supply from grid)** | **50.84 kWh** |
| ใช้ไฟรวมวันนี้ (Consumed by appliances) | 179.30 kWh |
| ขายไฟออก (Fed to grid) | 0.00 kWh — ใช้เองหมด ไม่ขายออก |

กราฟ Energy Trend มี 3 เส้นแยกกัน: PV output / **Power from grid** / **Consumed by appliances**

ตัวเลขพวกนี้จะเกิดขึ้นไม่ได้เลยถ้าไม่มีอุปกรณ์วัดที่จุดเชื่อมต่อการไฟฟ้า →
**ระบบมี Smart Power Sensor อยู่แล้ว ไม่ต้องซื้อเพิ่ม**

> เนื่องจากไม่เคยขายไฟออก (Fed to grid = 0) ทิศทางมิเตอร์จึงน่าจะเป็นบวก = ซื้อไฟเข้า
> คือ `METER_SIGN = "1"` ตามค่าเริ่มต้น แต่ยังต้องยืนยันด้วยขั้นตอนที่ 7 อยู่ดี

หลัง deploy ให้เรียก **`/api/probe-devices`** หนึ่งครั้ง จะได้รายการอุปกรณ์ทั้งหมด
พร้อมค่าดิบทุกฟิลด์ ทำให้รู้ทันทีว่ามิเตอร์อยู่ที่ `devTypeId` ไหนและใช้ชื่อฟิลด์อะไร
ไม่ต้องเดาแล้วไล่แก้ทีละรอบ

### ผลการตรวจ Kiosk View (สรุปแล้ว: ใช้แทน Northbound API ไม่ได้)

ตรวจจากหน้า Kiosk จริงของโรงงานนี้แล้ว มีแต่ข้อมูลฝั่งผลิตล้วน ๆ:
Real-Time power / Yield today / this month / this year / Total yield / Power chart /
Environmental benefits / Overview

**ไม่มีข้อมูลฝั่งซื้อไฟหรือโหลดรวมเลย** ซึ่งเป็นสองตัวที่ระบบนี้ต้องใช้ →
ยังต้องใช้บัญชี Northbound API + มิเตอร์อยู่ดี

โค้ดฝั่ง Kiosk (`src/kiosk.js` + `/api/probe-kiosk`) ยังเก็บไว้ เผื่อโรงงานอื่นที่ตั้งค่า
Kiosk ต่างออกไป หรือถ้าติดมิเตอร์เพิ่มแล้วรายการใน Kiosk เปลี่ยน — เรียก `/api/probe-kiosk`
จะบอกได้ทันทีว่ามีฟิลด์ฝั่งใช้ไฟโผล่มาหรือยัง

> ✅ แต่ Kiosk มีประโยชน์จริงอย่างหนึ่ง: **เอา URL ไปเปิดค้างบนทีวีหน้าออฟฟิศได้เลยวันนี้**
> ฟรี ไม่ต้องตั้งอะไร (แค่รู้ว่าใครมีลิงก์ก็เปิดดูได้ และ URL หมดอายุทุก 1 ปี)

## สิ่งที่ต้องมีก่อนเริ่ม

1. **บัญชี Northbound API ของ FusionSolar** — ขอจากดีลเลอร์/ผู้ติดตั้งระบบโซลาร์ (คนละตัวกับ user ที่ใช้ล็อกอินแอพ) จะได้มาเป็นคู่ `username` + `system code`
2. **Smart Power Sensor (มิเตอร์) ที่จุดเชื่อมต่อการไฟฟ้า** — ⚠️ จำเป็น แต่**โรงงานนี้มีอยู่แล้ว** (ดูหลักฐานข้างบน)

   วิธีเช็คสำหรับที่อื่น: เข้าหน้า Monitoring → Overview ถ้าเห็นแผนภาพการไหลของไฟที่มี "Grid" กับ "Load" แยกจาก "PV" และมีตัวเลข "Supply from grid" แปลว่ามีมิเตอร์แล้ว
3. **บัญชี Cloudflare** (ฟรี) และ **บัญชี Telegram**

## ติดตั้ง

### 1) เตรียม Cloudflare

```bash
cd solar-guard
npx wrangler login                          # เปิดเบราว์เซอร์ให้ล็อกอิน
npx wrangler kv namespace create SOLAR_KV   # จะได้ id ยาว ๆ กลับมา
```

เอา `id` ที่ได้ไปใส่ใน `wrangler.toml` ตรงบรรทัด `ใส่_KV_NAMESPACE_ID_ตรงนี้`

### 2) สร้างบอท Telegram

1. แชทกับ [@BotFather](https://t.me/BotFather) → พิมพ์ `/newbot` → ตั้งชื่อ → จะได้ **token**
2. สร้างกลุ่ม Telegram ของพนักงาน แล้ว **เชิญบอทเข้ากลุ่ม**
3. หา chat id ของกลุ่ม: พิมพ์อะไรก็ได้ในกลุ่ม 1 ข้อความ แล้วเปิดลิงก์นี้ในเบราว์เซอร์

   `https://api.telegram.org/bot<TOKEN>/getUpdates`

   มองหา `"chat":{"id":-1001234567890` — เลขติดลบนั่นคือ **chat id ของกลุ่ม**

### 3) ใส่ค่าลับ

```bash
npx wrangler secret put FUSION_USER            # username ของ Northbound API
npx wrangler secret put FUSION_SYSTEM_CODE     # system code
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID       # เลขติดลบของกลุ่ม
npx wrangler secret put DASHBOARD_TOKEN        # ตั้งรหัสอะไรก็ได้ ไว้กันคนนอกเปิดหน้าจอ

# ไม่บังคับ
npx wrangler secret put TELEGRAM_BOSS_CHAT_ID  # chat id ของหัวหน้า ไว้ตามเวลาไม่มีใครรับเรื่อง
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
npx wrangler secret put RESEND_API_KEY         # หรือ BREVO_API_KEY
npx wrangler secret put MAIL_FROM              # เช่น solar@yourdomain.com
npx wrangler secret put MAIL_TO                # หลายคนคั่นด้วย ,
```

### 4) ปรับค่าใน `wrangler.toml`

อย่างน้อยต้องแก้ 3 อย่างนี้:

- `SITE_NAME` — ชื่อโรงงาน
- `SYSTEM_KWP` — ขนาดระบบโซลาร์ที่ติดตั้ง
- `LOAD_SHED_LIST` — **รายการอุปกรณ์ที่ให้พนักงานไปปิด พร้อมตัวเลข kW จริงและชื่อคนรับผิดชอบ** (สำคัญที่สุด ควรใช้แคลมป์มิเตอร์วัดจริงสักครั้ง)

ส่วนเกณฑ์ `WARN_IMPORT_KW` / `CRIT_IMPORT_KW` **อย่าเพิ่งตั้งจริง** — ดูขั้นตอนจูนในหัวข้อถัดไป

### 5) Deploy

```bash
npx wrangler deploy
```

จะได้ URL ประมาณ `https://solar-guard.<ชื่อบัญชี>.workers.dev`

### 6) เช็คว่าใช้ได้

```bash
# ทดสอบส่งข้อความเข้ากลุ่ม
curl "https://solar-guard.xxxx.workers.dev/api/test-alert?k=DASHBOARD_TOKEN"

# ดูอุปกรณ์ทั้งหมด + ค่าดิบทุกฟิลด์ (เรียกอันนี้ก่อน จะรู้ว่ามิเตอร์อยู่ตรงไหน)
curl "https://solar-guard.xxxx.workers.dev/api/probe-devices?k=DASHBOARD_TOKEN"

# ลองดึงข้อมูลจาก FusionSolar 1 รอบ
curl "https://solar-guard.xxxx.workers.dev/api/poll?k=DASHBOARD_TOKEN"

# เปิดใช้คำสั่ง /ack /status /mute ในกลุ่ม (เรียกครั้งเดียวพอ)
curl "https://solar-guard.xxxx.workers.dev/api/setup-webhook?k=DASHBOARD_TOKEN"
```

### 7) ⚠️ ตรวจทิศทางมิเตอร์ (ข้ามไม่ได้)

**ตอนกลางคืน** (ไม่มีแดด ต้องซื้อไฟจากการไฟฟ้าแน่นอน) เรียก:

```bash
curl "https://solar-guard.xxxx.workers.dev/api/poll?k=DASHBOARD_TOKEN"
```

ดูค่า `sample.grid`

- ถ้าเป็น **บวก** → ถูกแล้ว ไม่ต้องแก้อะไร
- ถ้าเป็น **ลบ** → มิเตอร์นับกลับทาง ให้แก้ `METER_SIGN = "-1"` ใน `wrangler.toml` แล้ว `npx wrangler deploy` ใหม่

ถ้าตั้งผิด ระบบจะเตือนตอนที่แดดดีที่สุด ซึ่งตรงข้ามกับที่ควรจะเป็น

### 8) เปิดหน้าจอติดผนัง

`https://solar-guard.xxxx.workers.dev/?k=DASHBOARD_TOKEN`

เอาคอม/แท็บเล็ตเก่าเปิดค้างไว้หน้าออฟฟิศ กดปุ่ม `🔇 เปิดเสียงเตือน` ครั้งเดียว แล้วเวลาสถานะแดงจะมีเสียงไซเรนออกลำโพงเครื่องนั้น (รายละเอียดใน [`docs/SIREN.md`](docs/SIREN.md))

## จูนเกณฑ์ยังไงไม่ให้พนักงานเบื่อ

**อย่าเดาตัวเลข** — วิธีที่ใช้ได้จริง:

1. **สัปดาห์ 1–2**: ตั้ง `WARN_IMPORT_KW = "9999"` ไว้ก่อน ระบบจะเก็บข้อมูลอย่างเดียวโดยไม่เตือนเลย
2. เปิด dashboard ดูกราฟ ว่าปกติแล้วโรงงานซื้อไฟอยู่กี่ kW ช่วงไหนพุ่ง
3. **ตั้งเหลือง** = ค่าที่เกินประมาณ 20% ของเวลาทำงาน / **ตั้งแดง** = ค่าที่เกินแค่ 5%
4. **สัปดาห์ที่ 4**: นับจำนวนข้อความต่อวัน — ถ้าเกิน 3 ครั้ง/วัน ให้ขยับเกณฑ์ขึ้น อย่าปล่อยให้คนชิน

**ข้อยกเว้น: เกณฑ์เพดานการไฟฟ้า (`DEMAND_LIMIT_KW` / `DEMAND_TARGET_KW` / `DEMAND_ACTION_KW`) ห้ามแก้** มันคือเส้นตายจริง ไม่ใช่ค่าที่ปรับตามความรู้สึกได้

เหตุผลเต็ม ๆ อยู่ใน [`docs/ALERTING.md`](docs/ALERTING.md) หัวข้อ 3 และ 11

## เปิดใช้การตัดโหลดอัตโนมัติ

ค่าเริ่มต้นคือ `AUTOSHED_MODE = "off"` (เตือนคนอย่างเดียว) **อย่าเปิดเป็น `on` ทันที** ให้ไล่เป็นเฟส:

| เฟส | ตั้งค่า | ทำอะไร | นานแค่ไหน |
|---|---|---|---|
| 1 | `off` | เก็บข้อมูล ดูว่าพีคจริงอยู่ที่เท่าไหร่ เกิดตอนไหน | 2 สัปดาห์ |
| 2 | `dryrun` | ระบบบอกว่า "ถ้าเปิดใช้จริงจะสั่งปิด X" แต่ไม่สั่งจริง | 2 สัปดาห์ |
| 3 | `on` + ใส่แค่ 1 โซน | เปิดจริงกับแอร์ที่กระทบคนน้อยที่สุดก่อน | 2 สัปดาห์ |
| 4 | `on` ครบทุกโซน | ใช้เต็มระบบ | – |

สิ่งที่ต้องเตรียม: วัด kW จริงของแต่ละโซนด้วยแคลมป์มิเตอร์ แล้วกรอกลงตัวแปร `ZONES` พร้อมตั้ง `protected: true` ให้ห้องเซิร์ฟเวอร์/ห้องคุมเครื่อง

> ⚠️ Cloudflare Workers สั่งรีเลย์ที่ IP ในโรงงานตรง ๆ **ไม่ได้** ต้องให้ตัวควบคุมในโรงงาน (ESP32) มาอ่าน `/api/zones` เอง — โค้ด ESP32 พร้อมใช้และเช็กลิสต์ความปลอดภัยอยู่ใน [`docs/AUTOSHED.md`](docs/AUTOSHED.md)

## ข้อจำกัดที่ควรรู้

- ⚠️ **ระบบบนคลาวด์ตัวเดียวรับประกัน 100% ไม่ได้ว่าจะกันทุกหน้าต่าง 15 นาทีได้ทัน** — ข้อมูลจาก FusionSolar ช้า 5–10 นาที + ดึงได้ทุก 5 นาที รวมแล้วอาจรู้ตัวตอนหน้าต่างเหลือไม่กี่นาที ถ้าเดิมพันคือค่าไฟแพงทั้งปี **ควรมีตัวคุมในโรงงานอ่านมิเตอร์ตรง ๆ เป็นชั้นที่สอง** อ่านรายละเอียดและของที่ต้องซื้อใน [`docs/AUTOSHED.md`](docs/AUTOSHED.md) หัวข้อ 2–3
- **FusionSolar จำกัดความถี่การเรียก** — ห้ามตั้ง cron ถี่กว่า 5 นาที ไม่งั้นจะโดนตอบ `failCode 407` แล้วข้อมูลจะขาด (โค้ดจัดการให้แล้วโดยข้ามรอบนั้นไป ไม่ยิงซ้ำ)
- **ข้อมูลช้าประมาณ 5–10 นาที** — FusionSolar เองก็อัปเดตข้อมูลเป็นรอบ ไม่ใช่ real-time เพราะฉะนั้นระบบนี้เหมาะกับ "โหลดที่ค้างอยู่นาน ๆ" เช่นแอร์ ไม่เหมาะกับการจับ spike สั้น ๆ ระดับวินาที
- **พีคของเดือนคำนวณจากข้อมูลที่ระบบเห็น** ซึ่งอาจต่างจากที่มิเตอร์การไฟฟ้าบันทึกเล็กน้อย (ความถี่การสุ่มต่างกัน) ให้ใช้เป็นสัญญาณเตือน ไม่ใช่ตัวเลขทางบัญชี — ตัวเลขจริงดูจากบิลค่าไฟ
- **ต้องมีมิเตอร์** ถ้าไม่มี Smart Power Sensor จะใช้ไม่ได้ (ดูหัวข้อ "สิ่งที่ต้องมีก่อนเริ่ม")
- **ตัวเลข kW ในรายการอุปกรณ์เป็นค่าที่กรอกเอง** ระบบไม่ได้วัดจริงว่าปิดแอร์แล้วลดได้เท่าไหร่ ควรวัดด้วยแคลมป์มิเตอร์ครั้งเดียวแล้วกรอกให้ตรง
